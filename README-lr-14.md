### ЛР 14 SOLID
## Тема: Применение принципов SOLID в Android-приложении (Paging Lab 11)
## 1. Анализ нарушений
   SRP: В исходном коде функция PostListScreen содержала логику сетевого запроса (RetrofitClient), управление состоянием загрузки и отрисовку UI. Это усложняло тестирование и поддержку.
   DIP: Экран напрямую зависел от конкретного объекта RetrofitClient. Замена источника данных (например, на моковые данные) требовала изменения кода экрана.
## 2. Проведённый рефакторинг
   Для SRP: Вынес логику загрузки данных и хранения состояния в класс PostListViewModel. Функция PostListScreen теперь отвечает только за отображение (UI).
   Для DIP: Введён интерфейс PostRepository. ViewModel зависит от интерфейса, а не от конкретной реализации сети. Реализация PostRepositoryImpl инкапсулирует работу с PostApi.
## 3. Результаты
   Код стал модульным.
   PostListScreen теперь легко тестировать (можно подменить ViewModel).
   Можно легко заменить источник данных (например, добавить кэш), не меняя код экрана.

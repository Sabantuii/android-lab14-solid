# Отчёт по лабораторной работе 14: Принципы SOLID

## 1. Анализ нарушений

### SRP (Single Responsibility Principle)
- **Нарушение:** `PostListScreen` содержал логику сетевого запроса (`RetrofitClient.postApi.getPosts()`), управление состоянием (`remember`, `mutableStateOf`) и отображение UI
- **Проблема:** При изменении API придётся менять код экрана. Невозможно протестировать UI отдельно от сети

### DIP (Dependency Inversion Principle)
- **Нарушение:** Экран напрямую зависел от конкретного объекта `RetrofitClient`
- **Проблема:** Невозможно подменить источник данных (мок, кэш). Жёсткая привязка к Retrofit

### OCP (Open/Closed Principle)
- **Нарушение:** Добавление нового типа контента потребовало бы изменения `PostListScreen`
- **Проблема:** Код закрыт для расширения

### ISP (Interface Segregation Principle)
- **Соблюдено:** `PostApi` содержит только методы для работы с постами

### LSP (Liskov Substitution Principle)
- **Соблюдено:** `PostRepositoryImpl` корректно реализует контракт `PostRepository`

## 2. Рефакторинг

### Что добавлено:
1. `PostRepository` — интерфейс для абстракции источника данных (DIP)
2. `PostRepositoryImpl` — реализация репозитория (DIP)
3. `PostListViewModel` — управление состоянием и логикой (SRP)
4. Комментарии `// SRP:` и `// DIP:` в коде

### Что изменено:
- `PostListScreen` теперь только отображает данные
- Сетевые запросы вынесены в `Repository`
- Состояние хранится в `ViewModel`
- `MainActivity` координирует создание зависимостей

## 3. репозиторий

- before-refactoring - это до изменений 
- main - это после изменений 

## 4. Вывод

После рефакторинга код стал модульным:
- Легче тестировать (можно подменить Repository на мок)
- Легче расширять (добавление кэша не затронет UI)
- Четкое разделение ответственности (UI, логика, данные)
